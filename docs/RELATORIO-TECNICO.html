mcp-winthor (wt.ai) — Servidor MCP para WinThor

Servidor MCP local que liga o ERP WinThor a assistentes de IA (Cursor, Claude, ChatGPT): NestJS, base analítica local em DuckDB, aplicativo desktop em Electron e instalador, com credenciais que não saem da máquina do usuário.

1. Visão geral

O wt.ai sobe na máquina do usuário, recebe a URL e as credenciais do WinThor numa interface local e expõe tools MCP (wt_*) a qualquer cliente compatível. Consultas pesadas de vendas e estoque leem uma base local (DuckDB, ingerida do WinThor); o restante vai direto à API do WinThor. Em vez de exportar planilha, o usuário pergunta ao assistente de IA.

2. Destaques de engenharia

  • Padrão MCP: servidor via @modelcontextprotocol/server em HTTP (/mcp), com tools agrupadas (servidor, vendas, estoque, financeiro, clientes…).
  • Arquitetura local-first: credenciais e dados ficam na máquina; ingestão para DuckDB acelera consultas analíticas e paginação.
  • NestJS modular com validação (class-validator, Zod), UI local em Handlebars e testes unitários e e2e (autenticação, ingestão, paginação, contrato HTTP).
  • Distribuição: app desktop Electron (electron-builder) e build-installer.sh que empacota via Docker.

5. Compilar, testar e executar

# servidor (desenvolvimento)
cd server
cp .env.example .env
npm install
npm run start:dev      # http://127.0.0.1:8787  (MCP em /mcp)
npm test && npm run test:e2e

# desktop
cd ../desktop
npm install && npm run dev

# instalador (via Docker)
./build-installer.sh

6. Produção e deploy

  • Distribuído como instalador desktop (Electron); não roda no Coolify.
  • Cada usuário aponta o cliente MCP para o servidor local (http://127.0.0.1:8787/mcp).

7. Variáveis de ambiente

Este repositório não usa variáveis de ambiente.

8. Observações importantes

  • Credenciais do WinThor ficam locais; nunca versione o .env do servidor.
  • Documentação: docs/arquitetura.md e docs/casos-de-uso.md.
